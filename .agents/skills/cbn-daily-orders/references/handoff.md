# 交接与物流

向客户发送订单表前，核对实际 To/Cc、品牌、附件范围和用户授权。DozoFreesh 正式订单与样品可随同一封邮件交接。所有日期使用东京时间。

1. 用 `handoff --action reserve` 登记本次选定附件，程序校验附件内容、同店订单和 SKU 的现有交接状态。登记成功后发送已经核对的附件。
2. 确认已发记录后，用同批次、同客户范围执行 `confirm`，`--reference` 填实际邮件或交接记录编号。确认时再次核对附件哈希；若附件已变，核对实际已发附件并恢复对应原件后再确认，不能把发送结果不明的记录当成成功。相同记录可重复确认。以后出表自动跳过同店同订单 SKU 的已交接行。
3. 发送超时或结果不明时查询实际已发送记录。确认送出后 `confirm`，确认未送出后 `release`。等待确认的行在后续批次进入 `handoff-issues.json`。
4. 对已登记订单的数量、地址、电话或其他实际交接字段有变化时，整单进入复核清单。核对原客户的处理进度后再决定如何更正。

```sh
"$PYTHON" "$SKILL/scripts/cbn.py" --workspace "$WORKSPACE" handoff \
  --batch "$BATCH" --groups doz,sample --action reserve
```

核对已发送记录后，将最后一项改为 `--action confirm --reference "$SENT_RECORD_ID"`。一次登记一个客户，groups 可用 `smallFace`、`papaya`、`doz`、`sample`，水果茶同封邮件可用 `doz,sample`。零订单的类别不需登记。仅出表的历史复验批次用于检查结果。

交接台账存放在客户工作区，升级继续使用相同台账。首次切换时核对旧流程的已发附件，已发状态从实际登记开始累计。

需补录旧流程已发记录时，取得当时的原始导出、实际已发附件范围和发件记录编号。用当时日期及该客户 `--groups` 执行 `prepare --mode live`，为补账生成批次，再对确已发送的类别执行 `reserve` 和 `confirm --reference 实际记录编号`。这组命令只登记台账；不要重新发送旧附件。之后用最新待发货导出正式出表；数量或联系资料发生变化的旧订单会进入复核。缺少原始导出或发件证据时，先由运营员查明，不能把当前资料推定为旧交接内容。历史核算和测试继续使用 `--mode replay`，与补录业务记录区分。

水果茶物流方的 `客户订单编号` 对应 TikTok `注文ID`，物流方的 `订单编号` 是其内部编号。核对原始追踪号、配送业者和 SKU 及数量。多 SKU 共用单号须有逐 SKU 的完整反馈和多件商品数量，或明确的整单同包确认。

需要分包或一单由仓库和客户分别发货时，运营员在后台该订单点 `追跡情報を追加`（添加追踪信息），选择本包商品和数量，填该包单号并提交。批量回填完成后检查平台校验结果、最终送信及实际状态。部分成功时先核对成功行，再处理剩余行。
